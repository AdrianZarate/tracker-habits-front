# Reliable core — Stage 2

Make daily habit tracking reliable across reloads, account timezones, session expiry and user boundaries. Stage 2 is authorized; Stage 3 habit redesign and public deployment are not.

## Contract and constraints
- User chose persisted account IANA `timeZone`, initially detected by browser at Google login. First assignment only; later logins/devices do not silently change it. Legacy missing timezone uses UTC until assigned.
- Preserve every historical log's stored date label. Derive new account-local day/month labels with Intl and store them as the existing UTC-midnight Date anchors; never shift legacy logs or change unique indexes.
- History remains the current calendar month (now account-local). Owned inactive habits/history remain viewable; complete requires active ownership, deactivate stays idempotent, undo preserves existing owner-scoped semantics.
- Add owner-scoped GET habit ID; missing/non-owned returns equivalent 404. Static `/habits/logs` must precede dynamic ID route.
- Preserve Google-only auth and Stage 1 landing. No new app dependencies, password flow, reminder/stats work or database migrations.
- API pre-existing package.json class-validator change and yarn.lock remain byte-preserved, excluded from our commits. API uses Yarn1.22.22; frontend pnpm12.8.1 with install scripts disabled.
- Explicit user override: all commits on master in each repository, no feature branch/chaining/push/PR. Native review each committed work unit against its prior boundary, never include unrelated dirty API overlays.
